# 今日破防中国版：自适应 AI 自动发帖设计

## 目标与范围

在现有 AI 发帖结构上完成五个明确标注身份的 AI 机器人、至少 300 条中文模板、自适应每日配额、Asia/Shanghai 随机发布时间、安全幂等的 Supabase Cron 调度、正确的前端作者展示，以及可验证的数据库、GitHub 和 Vercel 发布流程。

本次不实现 AI 点赞、评论、关注、通知、聊天、登录或大模型生成，也不修改 `BreakToday-Global`。

## 配置模型

调度规则集中存放于 `app_settings`，至少包含：

- `ai_auto_posting_enabled=true`
- 真人帖数量到 AI 配额范围的四档规则
- 四个 Asia/Shanghai 发布时间段
- 单机器人每日通常上限 2、绝对上限 3
- 单机器人最小间隔 240 分钟
- 全局 AI 帖最小间隔 30 分钟
- 模板冷却期 30 天
- 各时间段允许的最大候选数量和机器人偏好

数据库函数从同一配置源读取规则，避免在多个代码或 SQL 文件中散落相同常量。

## 每日计划与动态配额

系统按 Asia/Shanghai 自然日维护每日状态和最多八个候选发布时间。候选时间随机分布于：

- 08:00–10:00
- 12:00–14:00
- 18:00–20:00
- 22:00–次日 01:00

候选分钟每天重新生成且避开整点。同一时段最多一至两条候选，两条实际 AI 帖至少间隔 30 分钟。机器人在执行时按时间偏好、当日计数和最近发帖时间选择，因此允许部分机器人当天零发帖。

每个上海自然日为每个活跃度档位产生稳定的随机目标：

- 真人帖少于 5：6–8 条
- 真人帖 5–14：4–6 条
- 真人帖 15–29：2–4 条
- 真人帖至少 30：0–2 条

当真人帖子数量跨档时，当日目标只能维持或下降，不能因重复调用而重新随机上升。实际 AI 数量达到当前目标后，后续候选自动跳过。

## 幂等调度与数据库事务

Supabase Cron 每分钟调用一次受限数据库入口函数。入口函数使用事务级 advisory lock，确保并发调用只有一个执行者；调度日志对“上海日期 + 候选槽位”设置唯一约束，确保同一分钟或重复 Cron 调用不会重复消费候选槽位。

单次执行在一个数据库事务中完成：

1. 读取总开关和配置。
2. 获取或生成当日状态和候选槽位。
3. 重新统计当天真人帖和 AI 帖。
4. 计算并只下调动态目标。
5. 检查候选时间、全局 30 分钟间隔和槽位唯一键。
6. 选择当日少于绝对上限、最近四小时未发帖且符合时间偏好的机器人。
7. 选择 30 天未使用、`used_count` 较低、`last_used_at` 较早且句式分类未连续出现的模板。
8. 创建 AI 帖，更新模板统计并写入成功日志。

所有跳过和失败结果写入有限、可诊断的调度日志。总开关关闭时入口函数立即返回，不创建或占用发帖槽位。

## 权限与安全

- `ai_bots`、`ai_post_templates`、`app_settings`、每日状态和调度日志全部启用 RLS。
- 普通用户仅能读取 AI 作者展示所需的机器人公开信息。
- 模板、内部配置、每日状态和调度日志不向 `anon` 或 `authenticated` 开放。
- 所有 AI 发帖与调度函数撤销 `PUBLIC`、`anon`、`authenticated` 的执行权限。
- Cron 任务由数据库受信角色直接调用调度函数；不通过浏览器、Vercel API 路由或 Edge Function 传递 service-role 密钥。
- 普通用户不能直接插入或更新 `posts`，只能调用现有真人发帖 RPC；该 RPC 不接受 `is_ai_post` 或 `ai_bot_id` 参数。
- AI 机器人不创建 Supabase Auth 用户。若现有 `posts.user_id` 外键要求对应 `profiles` 行，只保留不可登录的关系占位记录，并确保前端 AI 作者信息始终来自 `ai_bots`。
- `.env.local`、service-role key、Supabase secret 和 Vercel 凭证不得进入 Git。

## 前端作者展示

统一作者数据结构为：

```ts
type PostAuthor = {
  id: string;
  displayName: string;
  avatarUrl: string;
  isAi: boolean;
  aiLabel: string | null;
};
```

真人帖子从 `profiles` 映射，AI 帖子从 `ai_bots` 映射。首页、详情页、点赞/互动相关列表和评论上下文复用同一映射和轻量徽标组件。AI 帖仍可被真人点赞、评论和分享，但 AI 作者不会进入注册、登录或真人资料编辑流程。

## Vercel 与发布

删除 Vercel 小时级 Cron 配置以及不再使用的 `/api/ai/cron` 路由。应用继续由 GitHub `main` 自动部署到 Vercel，但后台发帖完全由 Supabase Cron 承担。这样可以消除 Hobby 套餐对小时级 Vercel Cron 的部署阻断。

- 目标启用机器人恰好 5 个，UUID 固定。

- 通过受信数据库角色创建一条测试 AI 帖，记录帖子 ID，验证模板统计和日志后删除测试帖，并恢复或清理测试产生的统计和日志。
